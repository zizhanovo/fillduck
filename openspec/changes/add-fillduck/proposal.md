## Why

网上的表单每填一次都要重新敲一遍姓名、电话、地址、公司信息。遇到政务类老网站更麻烦，下拉要层层点选，改一个字段会连带清空另一个，点「上一步」还会让提交直接失败。2026-09-17 我们实测跑通了全国12315举报的整套填法，证明「按站点写好的配方去调用页面自己的控件」可以稳定地一次填对。现有开源项目要么已经停更（Form-O-Fill），要么只填假数据（Fake Filler），要么是每一步都调大模型的通用 agent，成本高、结果不稳定。所以值得做一个普通人装上就能用的「填鸭 FillDuck」：资料存一次，表单填一口。

## What Changes

- 新增**资料库**：本机保存多份资料卡（个人、公司、案件等），每张卡由标准字段加自定义字段组成，支持导入导出。
- 新增**填写引擎**：一份能注入页面运行的引擎，执行「配方」。
  - **通用配方**：在任意页面按 autocomplete 属性、标签文字、关键词，把资料卡字段匹配到输入框，只填空字段，不碰密码框。
  - **站点配方**：声明式地描述某个站点每一步的字段、依赖顺序和组件动作（输入后点候选项、层级选择、附件注入等）。
  - **安全底线**：任何配方都不会自动点最终提交。
- 新增首个**站点配方**「12315 举报」：覆盖须知、选企业、举报人、业务信息四步，已实测验证。
- 新增 **Chrome 插件**（MV3 侧边栏）：管理资料卡，选附件，「一口填完当前页」，展示逐字段结果。
- 新增 **Agent skill**：遇到没有配方的陌生表单时，由 agent 读页面、查资料卡来填，也可以据此写出新配方。插件本身不内置大模型，不存 API Key。
- 新增**公开示范页**：以 12315 虚构案例演示整个流程，内含资料卡生成器、配方写法说明，以及插件和 skill 的下载。

## Capabilities

### New Capabilities
- `profile-vault`：资料卡的数据结构、标准字段、本机存储、导入导出与敏感信息约束
- `fill-engine`：配方格式、通用匹配、动作词表、字段依赖顺序、填后核对、不自动提交
- `site-recipe-12315`：12315 举报流程的站点配方及其必须满足的填写结果
- `browser-extension`：侧边栏交互，包括资料卡管理、配方选择、附件、结果反馈，以及权限约束
- `agent-skill`：agent 使用引擎与资料卡的流程、陌生表单的处理、生成配方、提交前人工确认
- `public-demo`：公开示范页的内容、隐私约束与生成器行为

### Modified Capabilities
（无）

## Impact

- 项目位于 `~/projects/fillduck`，零运行时依赖。
- 代码自写，采用 MIT 许可。借鉴 map-the-web（GPL）和 Skyvern（AGPL）时只参考思路，不拷贝代码或数据；Form-O-Fill、page-agent 为 MIT，如有引用需保留版权声明。
- 站点配方依赖目标站当前的页面结构，目标站改版后需要更新配方。
- 插件需要访问用户打开的任意网页，才能使用通用配方（按需注入，用户点按钮才执行）。
- GitHub 上已有同名仓库 `rockbenben/fillduck`（0 星，做扩展商店文案填写），与本项目领域不同，暂不改名。
